# 箭头函数与普通函数的区别

|          |                   语法格式                   |       `new` 和原型 `prototype`       |        `arguments`<br />`super`<br />`new.target`        |                        `this` 指向                        |                              `call`、`apply` 和 `bind`                               |
| :------: | :----------------------------------------: | :----------------------------------: | :-----------------------------------------------------: | :------------------------------------------------------: | :----------------------------------------------------------------------------------: |
| 普通函数 | `function(){}`<br />函数声明<br />函数表达式 |                  有                  |                           有                            |                           动态                           |                                   修改 `this` 值                                    |
| 箭头函数 | `() => {}`<br />函数表达式<br />无函数声明形式 | 没有<br />无 `prototype`，不能 `new` |                  没有<br />可调用外围                   | 箭头函数的 `this` 指向定义时，外层中第一个普通函数的 `this` | 箭头函数中的 `this` 是在箭头函数定义时就决定的，而且不可修改的（`call`、`apply`、`bind`） |

<div style="border-left: 4px solid #3498db; background-color: #EAF6FF; padding: 12px 16px; border-radius: 6px;">
<p><strong style="color: #1a5490;">【补充·表格与术语】</strong>表格新增的两处内容，以及一个容易误读的表述：</p>
<ul>
<li>“语法格式” 栏补了 <code>无函数声明形式</code>：箭头函数只以表达式存在，必须写在赋值右侧（<code>const f = () =&gt; {}</code>）或直接作为实参传入，没有独立的声明语句。</li>
<li>“<code>new</code> 和原型” 栏补了 <code>无 prototype，不能 new</code>：箭头函数没有 <code>prototype</code> 属性，缺少构造实例所依赖的原型链，所以 <code>new</code> 它会直接抛出 <code>TypeError</code>。</li>
<li>“可调用外围” 指的是：箭头函数自身<strong>没有</strong> <code>arguments</code>、<code>super</code>、<code>new.target</code>，但会沿作用域链读到外层最近那个非箭头函数中的它们；<code>this</code> 同理，箭头函数也没有自己的 <code>this</code>，表中 “定义时外层第一个普通函数的 <code>this</code>” 描述的就是被捕获的那个对象。</li>
</ul>
</div>

**为什么需要箭头函数**

- 消除函数二义性（函数的二义性：1、指令序列；2、构造器面向对象）
- 调用函数有两种方式：1、直接调用，比如 `Date()`；2、通过 `new` 关键字调用 `new Date()`
- ES6 中引入了类是为了告诉使用者函数只能通过 `new` 调用
- 同理箭头函数就只能表达函数只有指令序列的作用，不能通过 `new` 调用

<div style="border-left: 4px solid #3498db; background-color: #EAF6FF; padding: 12px 16px; border-radius: 6px;">
<p><strong style="color: #1a5490;">【补充·选型】</strong>箭头函数的 <code>this</code> 只认定义位置，下列场景要改用普通函数：</p>
<ul>
<li>作为对象方法时：<code>obj.get()</code> 里的箭头函数拿不到 <code>obj</code> 的 <code>this</code>，只有在外层先捕获 <code>this</code>（如 Vue 2 的 <code>data</code>、<code>created</code> 里写 <code>const vm = this</code>）再在箭头函数内使用才成立。</li>
<li>需要 <code>arguments</code> 对象时：箭头函数没有 <code>arguments</code>，改用剩余参数 <code>(...args) =&gt; {}</code>。</li>
<li>需要动态 <code>this</code> 的回调：<code>addEventListener</code> 里希望 <code>this</code> 指向触发元素时要用普通函数；<code>setTimeout</code> 里则相反，通常希望沿用外层 <code>this</code>，此时箭头函数更省事。Vue 2 的 <code>methods</code> 也要用普通函数，写成箭头函数会拿不到组件实例的 <code>this</code>。</li>
<li>需要作为构造函数、或要用 <code>new.target</code> 判断调用方式时：这两者箭头函数都不具备。</li>
</ul>
</div>

<p style="color: #1a5490; font-weight: 700;">【补充·验证】以上结论都能直接跑一遍确认：</p>

```js
function Outer() {
  this.name = 'doubao'
  this.get = () => this.name // 【补充】箭头函数捕获 Outer 实例的 this
}
const o = new Outer()
const fn = o.get
console.log(fn()) // 【补充】'doubao'，方法取出来后 this 依然正确
console.log(fn.call({ name: 'other' })) // 【补充】'doubao'，call 改不了箭头函数的 this

const arrow = () => 'hi'
new arrow() // 【补充】TypeError: arrow is not a constructor
```

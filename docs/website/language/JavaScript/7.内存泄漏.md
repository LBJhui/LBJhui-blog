# 前端常见内存泄漏及解决方案

内存泄漏：一个对象在不能再被使用的情况下仍然占用内存，这个对象就是内存泄漏。

<span style="color: #e74c3c;">【修正】原句为 “一个对象，再不能被使用的情况下，占用了内存”，句式不通，已改为 “在不能再被使用的情况下仍然占用内存”。</span>

<span style="color: #e74c3c;">【修正】原稿 “内存泄露” 与 “内存泄漏” 混用，已全文统一为 “内存泄漏”。</span>

<span style="color: #f39c12;">【待确认】下文排版层面（汉字与英文/数字间空格、代码含义单词加反引号、`DOM` 大小写统一等）已按规则全篇调整，不再逐处标注。</span>

## 引起内存泄漏的原因

### 意外的全局变量

由于 JS 对未声明变量的处理方式是在全局对象上创建该变量的引用。如果在浏览器中，全局对象就是 `window` 对象。变量在窗口关闭或重新刷新页面之前都不会被释放，如果未声明的变量缓存大量的数据，就会导致内存泄漏。

- 未声明变量

```javascript
function fn() {
  a = 'global variable'
}
fn()
```

<span style="color: #e74c3c;">【修正】原代码 `a =  global variable` 中字符串缺少引号，会直接抛出语法错误，已按单引号规范改为 `a = 'global variable'`。</span>

- 使用 `this` 创建的变量（`this` 的指向是 `window`）。

```javascript
function fn() {
  this.a = 'global variable'
}
fn()
```

<span style="color: #e74c3c;">【修正】同上，`this.a =  global variable` 缺少引号，已改为 `this.a = 'global variable'`。</span>

解决方法：

- 避免创建全局变量。
- 使用严格模式，在 JavaScript 文件头部或者函数的顶部加上 `'use strict'`。

<span style="color: #3498db; font-weight: 700;">【补充】严格模式需要写在引号内，即 `'use strict'`；只写 `use strict` 会被当作普通表达式语句，不会生效。</span>

### 闭包引起的内存泄漏

原因：闭包可以读取函数内部的变量，然后让这些变量始终保存在内存中。如果在使用结束后没有将局部变量清除，就可能导致内存泄漏。

1. 持有了不再需要的函数引用，会导致函数关联的词法环境无法销毁，从而导致内存泄漏。
2. 当多个函数共享词法环境时，会导致词法环境膨胀，从而导致出现无法触达也无法回收的内存空间。

```javascript
function fn() {
  var a = 'I m a'
  return function () {
    console.log(a)
  }
}
```

解决：将事件处理函数定义在外部，解除闭包，或者在定义事件处理函数的外部函数中。 <span style="color: #f39c12;">【待确认】原句 “或者在定义事件处理函数的外部函数中” 句意未完整，建议补全后再保留。</span>

比如：在循环中的函数表达式，能复用最好放到循环外面。

```javascript
// bad
for (var k = 0; k < 10; k++) {
  var t = function (a) {
    // 创建了 10 次函数对象。
    console.log(a)
  }
  t(k)
}

// good
function t(a) {
  console.log(a)
}
for (var k = 0; k < 10; k++) {
  t(k)
}
t = null
```

### 没有清理的 DOM 元素引用

原因：虽然别的地方删除了，但是对象中还存在对 DOM 的引用。

```javascript
// 在对象中引用 DOM
var elements = {
  btn: document.getElementById('btn')
}

function doSomeThing() {
  elements.btn.click()
}

function removeBtn() {
  // 将 body 中的 btn 移除，也就是移除 DOM 树中的 btn
  document.body.removeChild(document.getElementById('button'))
  // 但是此时全局变量 elements 还是保留了对 btn 的引用，btn 还是存在于内存中，不能被 GC 回收
}
```

<span style="color: #e74c3c;">【修正】原代码 `getElementById(btn)`、`getElementById(button)` 传入的是变量而非字符串，运行时会抛出 `ReferenceError`，已补上引号改为 `'btn'`、`'button'`。</span>

<span style="color: #f39c12;">【待确认】示例中两处 id 分别为 `'btn'` 与 `'button'`，实际使用时需统一为同一个 id，否则移除的节点与引用的节点并非同一个。</span>

解决方法：手动删除，`elements.btn = null`。

<span style="color: #3498db; font-weight: 700;">【补充】现在也可以用 `elements.btn.remove()` 直接把节点从 DOM 树中摘除，但解除引用这一步仍不能省 —— 移除节点与释放引用是两件独立的事。</span>

### 被遗忘的定时器或者回调

定时器中有 DOM 的引用，即使 DOM 删除了，但是定时器还在，所以内存中还是有这个 DOM。

```javascript
// 定时器
var serverData = loadData()
setInterval(function () {
  var renderer = document.getElementById('renderer')
  if (renderer) {
    renderer.innerHTML = JSON.stringify(serverData)
  }
}, 5000)

// 观察者模式
var btn = document.getElementById('btn')
function onClick(element) {
  element.innerHTML = 'I m innerHTML'
}
btn.addEventListener('click', onClick)
```

<span style="color: #e74c3c;">【修正】原代码中 `getElementById(renderer)`、`getElementById(btn)`、`addEventListener(click, onClick)` 均缺少引号，且 `element.innerHTMl` 大小写有误（应为 `innerHTML`），已一并修正。</span>

解决方法：

- 手动删除定时器和 DOM。
- `removeEventListener` 移除事件监听。

<div style="border-left: 4px solid #3498db; background-color: #EAF6FF; padding: 12px 16px; border-radius: 6px;">
<p><strong style="color: #1a5490;">【补充·重要】</strong>“手动删除” 需要可操作的落点：调用 `setInterval` / `setTimeout` 时必须保存返回的 id，销毁时再 `clearInterval` / `clearTimeout`；解绑事件时必须传入与注册时相同的函数引用，因此匿名函数写法无法解绑。</p>

```javascript
var timerId = setInterval(render, 5000)

function destroy() {
  clearInterval(timerId) // 定时器不清，回调会一直间接持有 DOM
  window.removeEventListener('resize', onResize) // 必须传入同一个函数引用
}
```

<p>预期结果：销毁后定时器 id 置 `null`，事件监听数量回到注册前的值。</p>
</div>

## Vue 中容易出现内存泄漏的几种情况

在 Vue SPA 开发应用，那么就更要当心内存泄漏的问题。因为在 SPA 的设计中，用户使用它时是不需要刷新浏览器的，所以 JavaScript 应用需要自行清理组件来确保垃圾回收以预期的方式生效。因此开发过程中，你需要时刻警惕内存泄漏的问题。

<span style="color: #3498db; font-weight: 700;">【补充】下文示例均使用 Vue 2 的生命周期钩子：Vue 3 中 `destroyed` 已改名为 `unmounted`，`beforeDestroy` 已改名为 `beforeUnmount`，迁移时需同步替换。</span>

### 全局变量造成的内存泄漏

声明的全局变量在切换页面的时候没有清空。

```vue
<template>
  <div id="home">这里是首页</div>
</template>
<script>
export default {
  mounted() {
    window.test = {
      // 此处在全局 window 对象中引用了本页面的 DOM 对象
      name: 'home',
      node: document.getElementById('home')
    }
  }
}
</script>
```

<span style="color: #e74c3c;">【修正】原代码 `name: home` 与 `document.getElementById(home)` 中的 `home` 是未定义变量，已补引号改为字符串 `'home'`。</span>

解决方案：在页面卸载的时候顺便处理掉该引用。

```javascript
destroyed() {
  window.test = null // 页面卸载的时候解除引用
}
```

### 监听在 window/body 等事件没有解绑

特别注意 `window.addEventListener` 之类的事件监听。

```vue
<template>
  <div id="home">这里是首页</div>
</template>

<script>
export default {
  mounted() {
    window.addEventListener('resize', this.func) // window 对象引用了 home 页面的方法
  }
}
</script>
```

<span style="color: #e74c3c;">【修正】原代码 `addEventListener(resize, this.func)` 中事件名缺少引号，已改为 `'resize'`。</span>

解决方法：在页面销毁的时候，顺便解除引用，释放内存。

```javascript
mounted() {
  window.addEventListener('resize', this.func)
},
beforeDestroy() {
  window.removeEventListener('resize', this.func)
}
```

<span style="color: #3498db; font-weight: 700;">【补充】`this.func` 必须是**同一个函数引用**：若注册时写 `this.func`、解绑时写 `this.func.bind(this)` 或箭头函数，解绑会静默失效，监听仍然存在。</span>

### 绑在 EventBus 的事件没有解绑

举个例子。

```vue
<template>
  <div id="home">这里是首页</div>
</template>

<script>
export default {
  mounted() {
    this.$EventBus.$on('homeTask', (res) => this.func(res))
  }
}
</script>
```

<span style="color: #e74c3c;">【修正】原代码 `$on(homeTask, ...)` 中事件名缺少引号，已改为 `'homeTask'`。同时该写法用箭头函数注册监听，`$off` 时拿不到同一函数引用，无法精确解绑，下方已给出修正写法。</span>

解决方法：在页面卸载的时候也可以考虑解除引用。

```javascript
mounted() {
  this.$EventBus.$on('homeTask', this.onHomeTask)
},
beforeDestroy() {
  this.$EventBus.$off('homeTask', this.onHomeTask)
},
methods: {
  onHomeTask(res) {
    this.func(res)
  }
}
```

<span style="color: #e74c3c;">【修正】原写法 `this.$EventBus.$off()` 不传参数会移除该实例上的**全部**监听，容易误伤其他组件；已改为按事件名 + 同一函数引用定向解绑。</span>

### Echarts

每一个图例在没有数据的时候都会创建一个定时器去渲染气泡，页面切换后，Echarts 图例是销毁了，但是这个 Echarts 的实例还在内存当中，同时它的气泡渲染定时器还在运行。这就导致 Echarts 占用 CPU 高，导致浏览器卡顿，当数据量比较大时甚至浏览器崩溃。

解决方法：加一个 `beforeDestroy()` 方法释放该页面的 chart 资源。我也试过使用 `dispose()` 方法，但是 `dispose` 销毁这个图例，图例是不存在了，但图例的 `resize()` 方法会启动，则会报没有 `resize` 这个方法；而 `clear()` 方法则是清空图例数据，不影响图例的 `resize`，而且能够释放内存，切换的时候就很顺畅了。

```javascript
beforeDestroy() {
  this.chart.clear()
}
```

<div style="border-left: 4px solid #3498db; background-color: #EAF6FF; padding: 12px 16px; border-radius: 6px;">
<p><strong style="color: #1a5490;">【补充·重要】</strong>如果组件确实不再复用，`dispose()` 才是彻底释放实例的做法，报 `resize` 缺方法的根因是实例销毁后仍挂在 `window` 的 `resize` 监听上。顺序应为：先移除监听，再 `dispose()`，最后把引用置 `null`。</p>

```javascript
beforeDestroy() {
  window.removeEventListener('resize', this.onResize)
  this.chart.dispose()
  this.chart = null
}
```

<p>验收标准：切换页面后 Performance monitor 中 JS heap 不再阶梯式上涨，且 `resize` 不再报错。</p>
</div>

### v-if 指令产生的内存泄漏

`v-if` 绑定到 `false` 的值，但是实际上 DOM 元素在隐藏的时候没有被真实地释放掉。

比如下面的示例中，我们加载了一个带有非常多选项的选择框，然后我们用到了一个显示/隐藏按钮，通过一个 `v-if` 指令从虚拟 DOM 中添加或移除它。这个示例的问题在于这个 `v-if` 指令会从 DOM 中移除父级元素，但是我们并没有清除由 Choices.js 新添加的 DOM 片段，从而导致了内存泄漏。

```vue
<div id="app">
  <button v-if="showChoices" @click="hide">Hide</button>
  <button v-if="!showChoices" @click="show">Show</button>
  <div v-if="showChoices">
    <select id="choices-single-default"></select>
  </div>
</div>
<script>
export default {
  data() {
    return {
      showChoices: true
    }
  },
  mounted: function () {
    this.initializeChoices()
  },
  methods: {
    initializeChoices: function () {
      let list = []
      // 我们来为选择框载入很多选项，这样的话它会占用大量的内存
      for (let i = 0; i < 1000; i++) {
        list.push({
          label: 'Item ' + i,
          value: i
        })
      }
      new Choices('#choices-single-default', {
        searchEnabled: true,
        removeItemButton: true,
        choices: list
      })
    },
    show: function () {
      this.showChoices = true
      this.$nextTick(() => {
        this.initializeChoices()
      })
    },
    hide: function () {
      this.showChoices = false
    }
  }
}
</script>
```

<span style="color: #e74c3c;">【修正】原代码 `new Choices( #choices-single-default , {...})` 的选择器缺少引号，且 `label: Item + i` 中的 `Item` 是未定义变量，已分别改为 `new Choices('#choices-single-default', {...})` 与 `label: 'Item ' + i`。</span>

在上述的示例中，我们可以用 `hide()` 方法在将选择框从 DOM 中移除之前做一些清理工作，来解决内存泄漏问题。为了做到这一点，我们会在 Vue 实例的数据对象中保留一个属性，并会使用 Choices API 中的 `destroy()` 方法将其清除。

```vue
<div id="app">
  <button v-if="showChoices" @click="hide">Hide</button>
  <button v-if="!showChoices" @click="show">Show</button>
  <div v-if="showChoices">
    <select id="choices-single-default"></select>
  </div>
</div>

<script>
export default {
  data() {
    return {
      showChoices: true,
      choicesSelect: null
    }
  },
  mounted: function () {
    this.initializeChoices()
  },
  methods: {
    initializeChoices: function () {
      let list = []
      for (let i = 0; i < 1000; i++) {
        list.push({
          label: 'Item ' + i,
          value: i
        })
      }
      // 在我们的 Vue 实例的数据对象中设置一个 `choicesSelect` 的引用
      this.choicesSelect = new Choices('#choices-single-default', {
        searchEnabled: true,
        removeItemButton: true,
        choices: list
      })
    },
    show: function () {
      this.showChoices = true
      this.$nextTick(() => {
        this.initializeChoices()
      })
    },
    hide: function () {
      // 现在我们可以让 Choices 使用这个引用，从 DOM 中移除这些元素之前进行清理工作
      this.choicesSelect.destroy()
      this.showChoices = false
    }
  }
}
</script>
```

## ES6 防止内存泄漏

前面说过，及时清除引用非常重要。但是，你不可能记得那么多，有时候一疏忽就忘了，所以才有那么多内存泄漏。

ES6 考虑到这点，推出了两种新的数据结构：`WeakSet` 和 `WeakMap`。它们对值的引用都是不计入垃圾回收机制的，也就是说，如果其他对象都不再引用该对象，那么垃圾回收机制会自动回收该对象所占用的内存。

```javascript
const wm = new WeakMap()
const element = document.getElementById('example')
wm.set(element, 'something')
wm.get(element)
```

<span style="color: #e74c3c;">【修正】原代码写成 `vm.set()` / `vm.get()`（应为 `wm`），且 `getElementById(example)` 与 `something` 均缺少引号，已修正为 `wm.set(element, 'something')`。</span>

上面代码中，先新建一个 `WeakMap` 实例。然后，将一个 DOM 节点作为键名存入该实例，并将一些附加信息作为键值，一起存放在 `WeakMap` 里面。这时，`WeakMap` 里面对 `element` 的引用就是弱引用，不会被计入垃圾回收机制。

注册监听事件的 listener 对象很适合用 `WeakMap` 来实现。

```javascript
// 代码 1
ele.addEventListener('click', handler, false)

// 代码 2
const listener = new WeakMap()
listener.set(ele, handler)
ele.addEventListener('click', listener.get(ele), false)
```

代码 2 比起代码 1 的好处是：由于监听函数是放在 `WeakMap` 里面，一旦 DOM 对象 `ele` 消失，与它绑定的监听函数 `handler` 也会自动消失。

<div style="border-left: 4px solid #f39c12; background-color: #FEF5E7; padding: 12px 16px; border-radius: 6px;">
<p><strong style="color: #b9770e;">【待确认】此处结论需要核实</strong>：代码 2 中 `listener.get(ele)` 取到的仍是 `handler` 本身，`addEventListener` 注册的监听由目标元素持有，仅靠 `WeakMap` 并不会让监听 “自动消失”；`ele` 被回收前仍应显式 `removeEventListener`。更典型的弱引用场景是用 `WeakMap` 给元素挂附加数据（如缓存、状态），主线仍是及时解绑。</p>
</div>

## 小结

<div style="border-left: 4px solid #3498db; background-color: #EAF6FF; padding: 12px 16px; border-radius: 6px;">
<p><strong style="color: #1a5490;">【补充·知识结构】</strong>原文按 “成因 → 方案” 逐条罗列，缺少收口。下面两张清单分别对应 “怎么记” 与 “怎么查”，可直接作为排查时的对照表。</p>
</div>

| 泄漏类型 | 触发条件 | 处理方式 |
| --- | --- | --- |
| 意外的全局变量 | 未声明变量直接赋值、`this` 指向 `window` | 开启 `'use strict'`，用 `let` / `const` 声明 |
| 闭包 | 长期持有不再需要的函数引用、循环内反复创建函数对象 | 解除闭包、把函数提到循环外、用完置 `null` |
| DOM 引用 | 对象或全局变量持有已移除的节点 | 同步 `elements.btn = null`，或 `remove()` 后清引用 |
| 定时器 / 回调 | `setInterval` 未 `clear`、监听未 `remove` | 保存 id，销毁时 `clearInterval` + `removeEventListener` |
| Vue 组件 | 全局变量、`window` 监听、EventBus、Echarts、第三方控件 | 统一在 `beforeDestroy` / `beforeUnmount` 中清理 |
| 需要给 DOM 挂数据 | 强引用导致节点无法回收 | 用 `WeakMap` / `WeakSet` |

排查思路（验证层）：

1. Chrome DevTools → Performance monitor 观察 JS heap 是否阶梯式上涨。
2. Memory → Heap snapshot，切换页面前后各拍一次，对比 `Detached DOM tree` 与 `(closure)` 数量。
3. 定位到持有链后，回到上表找到对应的清理点，补上解绑或置空逻辑。
